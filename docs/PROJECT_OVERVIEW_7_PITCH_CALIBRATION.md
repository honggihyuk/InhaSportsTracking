# 7부 — 경기장 보정 개선 (앵커 추적)

> **이전 문서**: [5부 — 자동 보정](./PROJECT_OVERVIEW_5_AUTO_CALIBRATION.md) · [6부 — GPU 모델](./PROJECT_OVERVIEW_6_GPU_MODELS.md)

6부 51절의 1 순위 한계("경기장 보정이 가장 큰 오차원")를 고쳤다. `sports_video_1.mp4` 는 자동 키프레임이 1 개(30 초)뿐이라 29~33 초 구간만 라인이 맞았고, 그 결과 선수 최고 속력이 12.5 m/s 로 나왔다.

## 52. 원인

| # | 원인 | 위치 |
|---|---|---|
| 1 | 자동 키프레임 교차 검증이 어긋난 쌍에서 하나를 지우고 **더 먼 이웃과 다시 비교** → 광류 누적 오차 때문에 맞는 키프레임까지 연쇄 삭제 (2 초 간격으로 찾은 6 개 중 1 개만 남음) | `autocalib.auto_keyframes` |
| 2 | 라인 정렬(ICP)의 타당성 검사가 화면 네 모서리를 썼는데, 위쪽 모서리가 관중석(지평선 너머)이면 **항상 거부** → 정렬 채택 64 / 1,054 프레임 | `pitch.LineRefiner._plausible` |
| 3 | 화면에 고정된 점수판·방송사 로고의 특징점이 느린 팬에서 RANSAC 정상점으로 섞여 카메라 움직임을 0 쪽으로 끌어당김 (0.5 초에 수십 cm~수 m 누적) | `video_analysis.camera_motion` |
| 4 | 키프레임 담당 구간이 바뀌는 지점에서 호모그래피가 한 번에 바뀜 → 모든 선수 속력이 동시에 튐 | `frame_homographies` |
| 5 | `H / H[2,2]` 저장: 화면 왼쪽 위가 지평선 너머면 부호가 뒤집혀, 역행렬의 w > 0 으로 '카메라 앞' 을 가리는 화면 오버레이가 라인을 못 그림 | `calibrate` |

## 53. 방법 (`pipeline/calib_track.py`)

```
자동 키프레임 (0.5 초 간격 단일 프레임 탐색, 이웃 투표 검증)
  → 앵커 추적: 0.1 초 간격으로 이웃 앵커에서 광류 예측 → 라인 정렬(ICP)
               → F1 < 0.75 면 예측값 주변 가설 1,000 개(경기장 x 배율·이동 등)를 일괄 채점해 다시 잡기
               → F1 ≥ 0.55 이면 앵커. 이미 있는 자동 키프레임보다 추적값이 더 맞으면 교체
  → 연결: 앵커 사이 프레임 = 왼쪽·오른쪽 앵커를 광류로 옮긴 두 값을 거리 비율로 혼합
  → 적응형 시간 평활화: 평소 σ 0.05 초, 보정이 미끄러지는 곳(경기장 고정점이 1.5 m/s 이상 움직여 보임)만 0.4 초
  → 프레임별 신뢰도 0~1: 가까운 앵커 신뢰도 × 거리 감소, 라인 F1, 미끄러짐 → calibration.confidence
  → 경기장 좌표 칼만+RTS: 신뢰도 낮은 프레임은 측정 잡음을 최대 30 배로 → 앞뒤 프레임으로 보간하듯 따라감
```

- **이웃 투표** (원인 1): 앞뒤 3 개·3 초 이내 이웃과 광류로 비교(허용 2 m + 1 m/초)해, 어긋남이 맞음보다 많은 키프레임만 제거.
- **ICP 타당성** (원인 2): 예측 호모그래피에서 카메라 앞(경기장 위)인 격자점만 비교.
- **정지 오버레이 제외** (원인 3): `CameraMotion` — 카메라가 움직이는 프레임에서 질감이 있는데 밝기가 그대로인 픽셀을 세어 8 프레임 이상이면 특징점에서 뺀다. 프레임당 +1.1 ms (8.6 → 9.7 ms). 이것만으로 키프레임 쌍 간 광류 일치 오차가 대부분 0.3~1.4 m → 0.1~0.4 m.
- **부호 정규화** (원인 5): 화면 아래 가운데 점의 동차 좌표가 1 이 되도록 나눠 저장(`calib_track.orient`).
- 수동 키프레임은 고정(추적값으로 바꾸지 않음). 라인 마스크가 없으면(실시간 모드 수동 보정) 키프레임 사이 혼합·평활화만 한다.

## 54. 결과 — sports_video_1 (같은 탐지 결과로 재보정)

탐지·추적은 그대로 두고 `scripts/recalibrate.py` 로 영상을 다시 읽어 카메라 움직임·라인 마스크·자동 보정을 새로 계산했다. 평가: `scripts/eval_calibration.py` (투영한 라인 모델 점 → 가장 가까운 검출 라인 픽셀 거리, 원본 px, 20 px 에서 자름. 정상 = 오차 중앙값 ≤ 5 px 이고 재현율 ≥ 0.5).

## 55. 비용 (RTX 5070 PC, CPU 계산)

| 단계 | 35 초 영상 (1,054 프레임) |
|---|---|
| 카메라 움직임 추정 (분석 중, 프레임당) | 9.7 ms (+1.1 ms) |
| 자동 키프레임 탐색 (0.5 초 간격 71 프레임) | 60 s |
| 앵커 추적·혼합·평활화·신뢰도 | 20 s |
| 영상 다시 읽기 (실시간 결과에 라인 마스크 만들기) | 33 s |
| 수동 보정, 라인 마스크 없음 (실시간 모드) | 0.6 s |

- **정밀 모드**: 분석(458 s) 뒤 자동 보정 약 80 s 추가.
- **실시간 모드**: 분석 중 추가 비용은 카메라 움직임 +1.1 ms/프레임뿐. 자동 보정 버튼(`/calibration/auto`)은 라인 마스크를 만들고 보정까지 약 2 분(영상 길이의 3.3 배). 수동 기준점 보정은 1 초 미만. 더 빨라야 하면 `auto_calibrate(every_s=1.0)` 으로 탐색을 절반으로 줄일 수 있다.

## 56. 사용

```bash
# 기존 분석 파일을 탐지 없이 새 보정으로 갱신 (GPU 불필요)
python scripts/recalibrate.py data/samples/sports_video_1.mp4 data/samples/analysis/sports_video_1.mp4.json --out uploads/analysis/sports_video_1.mp4.json
# 보정 품질 평가 (프레임별 결과는 --rows / --json)
python scripts/eval_calibration.py uploads/analysis/sports_video_1.mp4.json --every 0.2
# 전후 비교 이미지
python scripts/calibration_compare_images.py data/samples/sports_video_1.mp4 before.json after.json docs/report_screenshots/calibration
```

결과 JSON 변화: `calibration.method = 'anchored'`, `calibration.confidence` (프레임별 0~1), `anchors`, `tracked_anchors`, `recovered_anchors`, `replaced_keyframes`, `max_slide`. `line_fit` 은 없어졌고 `refined_frames` 는 신뢰도 ≥ 0.5 프레임 수다. `homographies` 는 부호 정규화된 값이다.

테스트: `tests/test_calib_track.py` (8 개) + `tests/test_autocalib.py` 이웃 투표 1 개 — 정지 오버레이 제외, 화면 위가 관중석인 장면의 라인 정렬, 광류 치우침 보정, 어긋난 키프레임 사이 점프 없음, 틀린 자동 키프레임 교체, 저신뢰도 프레임의 속력 억제.
