# 13부 — 경기 분석 화면: 팀 히트맵 · 패스 네트워크 · 팀 대형

> **이전 문서**: [4부 — 정밀 분석(경기 지표)](./PROJECT_OVERVIEW_4_PRECISE_ANALYSIS.md) · [9부 — 등번호](./PROJECT_OVERVIEW_9_JERSEY_OCR.md) · 후반기 보고서 향후 계획 3순위

## 기존 상태

`analysis/stats.py` 의 `compute()` 는 선수 지표·스프린트·점유·팀 대형(`shape`: 0.5 초 간격 무게중심·폭·길이·수비 라인)·5 m 격자 히트맵(`heatmaps`)을 이미 계산해 `/analysis/{name}/stats` 와 분석 결과 JSON 의 `stats` 로 내보냈다. 하지만 화면에는 팀 합계(점유율·거리·패스 수)와 선수 표만 있었고, 히트맵·대형·패스 관계를 보여 주는 화면은 없었다.

## 바꾼 내용

### 1. 패스 네트워크 (`analysis/stats.py` `pass_network()`)

`compute()` 반환값에 `pass_network` 키만 **추가**했다. 기존 키와 형식은 그대로다 (실제 샘플로 다시 계산해 기존 9 개 키가 바이트 단위로 같음을 확인).

```json
"pass_network": {
  "home": {"nodes": [...], "edges": [...], "passes": 0},
  "away": {
    "nodes": [{"id": 48, "jersey_number": null, "role": "player", "position": [6.5, 11.2], "passes": 1, "received": 1}],
    "edges": [{"a": 30, "b": 48, "count": 1, "a_to_b": 1, "b_to_a": 0}],
    "passes": 4
  }
}
```

| 항목 | 정의 |
|---|---|
| 패스 | 점유 이벤트(`possession()`) 중 같은 팀 선수로 소유자가 바뀐 `type == 'pass'` (턴오버 제외) |
| 노드 | 그 팀에서 패스를 주거나 받은 선수. `position` = 패스에 관여한 순간(주는 쪽 = 공을 떠나보낸 프레임, 받는 쪽 = 공을 잡은 프레임) 좌표의 평균. 그 프레임 좌표가 없으면 경기 전체 평균 위치(`mean_position`) |
| 등번호 | `identities` 에서 확정된 등번호(`players[id].jersey_number`), 없으면 `null` |
| 엣지 | 방향 없는 선수 쌍(`a < b`)별 패스 횟수 `count`, 방향별 `a_to_b` / `b_to_a` |

패스 순간의 위치를 쓰는 이유: 경기 전체 평균 위치는 공과 무관하게 뛰어다닌 위치까지 섞여, 패스 네트워크의 "누가 어디서 공을 주고받았나"를 흐린다.

### 2. 분석 화면 (`frontend/src/components/AnalysisViews.jsx`)

스테이지 아래 `below` 영역에 "경기 분석" 카드 하나를 전체 폭으로 붙였다(`App.jsx` 는 마운트 한 곳만 추가). 경기 지표(`stats`)가 있을 때만 보인다.

| 화면 | 경기장 위 표시 | 표 보기 |
|---|---|---|
| 히트맵 | 팀별 5 m 격자 밀도. 한 색(팀 색)의 투명도 램프, 가장 많은 칸 = 100 % | 공격 방향 기준 3 × 3 구역(수비·중원·공격 × 왼쪽·가운데·오른쪽) 점유 비율 |
| 패스 네트워크 | 원 = 선수(번호 = 등번호, 없으면 트랙 ID), 원 크기 = 관여 횟수, 선 굵기 = 패스 횟수. 선을 클릭하면 그 쌍의 첫 패스로 이동 | 선수 쌍별 패스 횟수·방향별 |
| 팀 대형 | 현재 프레임의 필드 선수 볼록 껍질, 수비 라인(세로선), 무게중심, 최근 10 초 무게중심 궤적 (두 팀) | 현재 프레임 폭·길이·수비 라인·무게중심 x·필드 선수 수 |

- **대형 시계열**: 폭 / 길이 / 수비 라인 / 무게중심 x 중 한 지표를 고르면 두 팀을 한 축(m)에 선으로 그린다(이중 축 없음). 초록 세로선 = 현재 시각, 마우스 = 십자선과 두 팀 값, 클릭 = 그 시각으로 영상 이동. 보정이 1 초 넘게 끊긴 구간은 선을 끊는다.
- **현재 시점 연동**: 모든 화면에 현재 프레임 선수 위치(작은 점)와 공(노란 점)을 겹친다. 히트맵·패스 네트워크는 "전체 경기 / 현재 시점까지"를 고를 수 있고, 현재 시점까지는 0.5 초 단위로 누적해 다시 계산한다.
- **이전 결과 호환**: 이미 저장된 분석 결과에는 `pass_network` 가 없다(지표는 분석·보정 때 계산해 JSON 에 저장됨). 화면은 이때 `stats.events` 의 패스와 `world` 좌표로 같은 규칙(`analysis.js` `passNetwork()`)으로 만든다. 샘플 영상에서 Python 결과와 JS 결과가 일치함을 확인했다. "현재 시점까지" 구간도 같은 함수를 쓴다.

### 3. 색

`dataviz` 스킬 규칙을 따른다: 팀 = 범주형(팀 색, `teamColors`), 히트맵 = 한 색상 순차(투명 → 팀 색), 선 2 px, 점 지름 ≥ 8 px + 표면색 테두리, 격자·축은 실선 헤어라인, 글자는 텍스트 색(팀 색 글자 없음), 툴팁은 보조이고 모든 값은 표 보기로도 읽을 수 있다.

팀 색은 유니폼에서 뽑은 색이라 어두운 잔디 위에서 안 보일 수 있다. 샘플(`#c9d4dd` 홈 · `#5e4a47` 원정)은 원정 색이 잔디(`#13261A`) 대비 1.93:1 로 검증기에서 대비 경고가 났다. 그래서 분석 화면에서만 OKLab 밝기를 [0.56, 0.78] 로 옮기고(색상·채도 유지, `analysis.js` `vizTeamColor()`), 옮긴 두 색이 OKLab ΔE < 15 로 너무 비슷하면 기본 홈/원정 색(`#E5534B` / `#4A9BF0`)으로 바꾼다.

| 팀 색 | 잔디 대비 | 색각 이상 ΔE | 일반 ΔE | 비고 |
|---|---|---|---|---|
| 기본 `#E5534B` · `#4A9BF0` | ≥ 3:1 통과 | 24.5 | 30.9 | 6 개 검사 모두 통과 |
| 샘플 원본 `#c9d4dd` · `#5e4a47` | 원정 1.93:1 경고 | 43.3 | 43.7 | 밝기 밴드·채도 미달 |
| 샘플 보정 `#aeb9c2` · `#846f6b` | 둘 다 ≥ 3:1 통과 | 21.8 | 22.4 | 회색 계열 유니폼이라 채도 하한은 구조적으로 미달 → 범례·직접 라벨(번호)·표로 보완 |

## 남은 일

- **속도·스프린트 수치 확인은 섹터 A 병합 뒤**: 이 화면은 속도를 직접 쓰지 않지만, 점유 판정(→ 패스 네트워크)과 대형은 같은 `world` 좌표를 쓴다. A 가 좌표 평활·이상값 처리를 바꾸면 패스 수·노드 위치·대형 수치가 달라질 수 있다.
- 샘플 영상은 35 초에 패스가 4 회(모두 원정)뿐이라 패스 네트워크가 성기다. 긴 경기 영상으로 다시 확인이 필요하다.
- 저장된 결과의 `stats.pass_network` 는 다시 분석하거나 보정을 저장해야 생긴다 (화면은 없어도 동작).
