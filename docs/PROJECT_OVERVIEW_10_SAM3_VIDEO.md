# 10부 — SAM3 영상 추적으로 트랙 끊김·ID 교체 바로잡기

> **이전 문서**: [3부 24절 로드맵 7번](./PROJECT_OVERVIEW_3_VLM.md) · [6부 — GPU 모델](./PROJECT_OVERVIEW_6_GPU_MODELS.md) · [9부 — 등번호](./PROJECT_OVERVIEW_9_JERSEY_OCR.md)

## 기존 방식

정밀 모드의 SAM3(`tracking/sam_refiner.py`)는 **프레임마다 따로** 쓴다: 그 프레임의 추적기 박스를 프롬프트로 `Sam3TrackerModel`(이미지 모드)에 넣어 마스크를 얻고, 마스크 최하단으로 발 위치(지면 접점), 마스크로 배경을 지운 유니폼 크롭을 만든다. 프레임 사이 마스크 전파는 없고, ID 는 BoT-SORT 박스 매칭과 후처리 트랙 잇기(위치·시간 비용)로만 정해진다. 그래서 선수가 겹치거나 가려지면 트랙이 끊기거나 두 선수의 ID 가 바뀐다.

## 바꾼 내용 (`tracking/sam_video.py`)

SAM3 영상 추적기(transformers `Sam3TrackerVideoModel`, 메모리 기반 마스크 전파)로 **위험 구간만** 다시 따라간다. 영상 전체를 전파하면 RTX 5070 에서 10 명 기준 초당 1.5 프레임이라 정밀 분석 시간이 두 배 이상 늘어나므로, 관련 선수 1~2 명만 30~40 프레임씩 전파한다 (초당 4~5 프레임, 약 2 GB).

| 단계 | 위험 구간 | 판단 |
|---|---|---|
| 끊김 잇기 | 트랙 A 가 화면 안에서 끝나고 1 초 안에 근처(박스 높이 3 배 이내)에서 트랙 B 가 시작 | A 의 마지막 박스로 전파한 마스크와 B 의 첫 박스가 IoU ≥ 0.5 면 B 를 A 로 잇는다 |
| ID 교체 | 두 트랙 박스가 IoU ≥ 0.3 으로 겹쳤다가 둘 다 10 프레임 이상 이어지는 장면 | 겹치기 8 프레임 전 박스로 두 선수를 전파해, 떨어진 뒤 비교한 프레임의 80 % 이상(최소 5 프레임)에서 A 박스가 B 마스크와, B 박스가 A 마스크와 더 잘 맞으면 겹침 구간 가운데부터 두 ID 를 바꾼다 |

- 후처리 트랙 잇기(stitch) 뒤, 공백 보간 전에 실행한다. 이은 트랙의 유니폼 색·크롭·탐지 라벨, 등번호 크롭(교체는 프레임 기준)도 함께 옮긴다.
- 지면 접점은 기존대로 프레임별 SAM3 마스크 최하단을 쓴다 (이미 정밀하고, 영상 전파 마스크는 저해상도 288×288 이라 더 정밀하지 않다).
- 결과 JSON `sam_video`: 이벤트 수, 이은 수, 교체 목록·근거(`swap_evidence`: 엇갈린 프레임 수, 평균 IoU 차이), 시간.
- 설정: `analysis.profiles.precise.sam_video: auto` (GPU 이고 후처리가 켜져 있을 때), `gpu_models.sam_video: facebook/sam3`. 실패하면 기존 추적 결과를 그대로 둔다.

## 평가 — sports_video_1 (정밀 모드 전체 분석, 등번호 인식 포함)

파인튜닝 RF-DETR + SAM3(프레임) + SigLIP2 + GLM-OCR, RTX 5070 12 GB. 기존 = SAM3 영상 추적 끔, 새 방식 = 켬. 트랙 지표는 등번호 재연결까지 끝난 최종 결과 기준.

| 지표 | 기존 | 새 방식 |
|---|---|---|
| 트랙 수 (전체 / 심판 제외) | 54 / 47 | **51 / 44** |
| 평균 · 중앙값 트랙 길이 (심판 제외) | 8.7 s · 6.7 s | **9.4 s · 7.5 s** |
| 끊김 (화면 안에서 끝나고 1 초 안에 근처에서 새 트랙 시작) | 4 | **1** |
| SAM3 가 이은 끊김 / 바로잡은 ID 교체 | — | 3 / 2 |
| 등번호 확정 트랙 (심판 제외) | 15 / 47 (31.9 %) | 14 / 44 (31.8 %) |
| 등번호 확정 트랙이 차지하는 선수 박스 | 56.4 % | 51.5 % |
| 분석 시간 (탐지~팀·등번호, 보정 제외) | 446 s | 728 s (SAM3 영상 추적 274 s) |
| 최대 VRAM | 3.9 GB | 5.1 GB |

**ID 교체 직접 확인**: 겹침 장면의 프레임을 4 프레임 간격으로 직접 봤다.
- 바꾼 2 건(64↔65 @ 10.6 s, 58↔64 @ 17.7 s)은 모두 **실제 ID 교체**였다 — 각각 흰 유니폼 선수 ID 가 바르사 선수로 넘어간 경우, 바르사 22 번·14 번이 겹친 뒤 ID 가 서로 바뀐 경우.
- 기준을 낮추면(엇갈림 비율 0 %) 3 건이 더 잡힌다: 10↔15 @ 10.5 s 는 달리던 선수의 ID 가 누워 있는 선수에게 넘어간 **실제 교체**(엇갈림 12/15 프레임, 이번 실행에서는 기준 80 % 바로 아래), 58↔64 @ 24.7 s·9↔58 @ 26.8 s 는 두 선수가 실제로 엇갈려 달리는 장면이라 **판단 보류**. 그래서 확실한 경우만 바꾸도록 80 % 기준을 뒀다.
- 등번호 확정 박스 비율이 조금 줄었다 (56 → 52 %). 새 방식 실행에서는 같은 팀·번호 충돌이 1 건 생겨 그 트랙이 미확정으로 돌아갔다 (기존 0 건).

## 한계와 다음 단계

1. **시간**: 겹침 장면이 많은 영상에서는 정밀 분석 시간이 크게 늘어난다 (이 영상 +274 s, 겹침 31 곳). 같은 시간대 장면을 한 세션으로 묶으면 줄일 수 있다.
2. 끊김은 후처리 트랙 잇기가 대부분 먼저 잇기 때문에 SAM3 가 맡는 경우는 적다 (4 곳 중 3 곳).
3. 두 선수가 실제로 엇갈려 달리는 장면과 ID 교체를 마스크만으로 구별하기 어려운 경우가 있다 → 보수적 기준. 등번호가 확정된 트랙끼리는 번호로 검증하는 방법이 다음 단계다.
4. 트랙 전체를 SAM3 영상 추적으로 대체하는 방식(BoT-SORT 대신)은 12 GB 에서 시간이 너무 길어 시도하지 않았다.
