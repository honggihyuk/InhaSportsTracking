## 1. 먼저, 잘한 점

두 리뷰어가 공통으로 꼽았거나 여러 섹터에서 반복해서 보인 습관입니다. 다음 작업에서도 그대로 가져가면 좋겠습니다.

1. **증상을 숨기지 않고 원인을 데이터로 좁혔습니다** (A). `MAX_SPEED`를 낮추면 숫자는 쉽게 사라집니다. 그렇게 하지 않고 `diagnose_speed.py`로 병합 이력과 보정 신뢰도를 기록해 후보 원인을 하나씩 지웠습니다. → [opus-1 잘한 점 ①]
2. **최적화를 넣으면서 결과가 같다는 것까지 증명했습니다** (B). 단위 테스트, 실제 SAM3 스모크(박스 227/227 일치), 전체 영상 두 번 실행 비교의 세 단계로 확인했습니다. 순차 의존성(앞 사건이 뒤 사건의 입력을 바꾸는 경우)도 놓치지 않았습니다. → [opus-2 잘한 점 1·2]
3. **판정의 근거를 결과에 남깁니다** (B). `link_iou`, `swap_evidence`, `votes`, `texts`가 저장되어 "왜 이 두 트랙이 합쳐졌는지"를 나중에 추적할 수 있습니다.
4. **하위 호환을 먼저 생각했습니다** (C). `compute()`에 `pass_network` 키 하나만 더했고, 그 키가 없는 예전 저장본은 프론트에서 다시 계산합니다.
5. **시각화 결정을 수치로 내렸습니다** (C). 원정 팀 색과 잔디의 대비가 1.93:1이라는 측정값에서 출발해 OKLab 밝기만 조정했습니다.
6. **안전한 기본값을 골랐습니다** (통합). 업로드 파일 이름의 경로 조작을 막았고, 에이전트 도구는 읽기 전용에 등록된 이름만 호출할 수 있습니다. 에이전트 루프에는 `max_steps` 상한과 도구 결과 6,000자 제한이 있습니다.
7. **한계를 정직하게 적었습니다.** "한 번씩 실행한 결과", "VRAM +33.9%", "사람이 단 정답과 대조한 정확도는 별도 지표"처럼 비용과 범위를 숨기지 않았습니다.
