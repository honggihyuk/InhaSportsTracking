## 1. 잘한 점

- `compute()`가 쓰는 점유 이벤트에서 팀 패스 합계와 네트워크를 함께 만든다. 한 선수 쌍을 한 선으로 표시하면서 양방향 횟수를 보존한다. `tests/test_pass_network.py:33`은 1→2 두 번과 2→1 한 번이 선 하나의 세 번으로 모이는지, 상대 선수에게 넘어간 공이 원정 패스로 집계되는지까지 구별한다.
- 서버의 `/analysis/{name}/stats`는 저장된 통계를 반환하고, App은 불러온 분석 결과의 통계를 화면에 전달한다. 전체 경기에서는 저장 격자와 네트워크를 재사용하고, 이전 저장본에 네트워크가 없으면 JS가 이벤트로 복원한다. 대형도 전체 시계열에는 서버 표본을, 현재 프레임의 외곽선에는 실제 좌표를 써서 각 화면의 시간 해상도를 살렸다.
- 기존 App의 카드·탭·표와 CSS의 글꼴·테두리·표면색 토큰을 재사용했다. 방송 영상과 3D 트윈 양쪽을 유지하면서 화면 아래에 분석 카드를 추가한 구성 덕분에, 패스를 클릭한 뒤에도 두 장면을 함께 비교할 수 있다. `04-pass-linked-video.png`에는 홈 패스의 61프레임과 두 패널이 함께 보인다.

## 2. 개선 제안

**질문** 사용자가 영상을 멈춘 프레임에서 아직 보지 않은 위치나 연결선을 읽을 수 있어야 할까? **선택지** 현재 프레임을 정확한 상한으로 쓰면 표와 영상이 일치하지만 누적 계산 비용을 관리해야 한다. 완료된 반초 경계까지만 집계하고 실제 끝 시각을 표시하면 지금의 갱신 빈도를 유지하면서 최대 반초의 지연을 설명할 수 있다. **학습 개념** 시간 구간의 포함 경계와 미래 데이터 누출.

### ② 점유 전환이 관측 공백을 건너고, 출발 시각이 수신 확정 직전으로 밀린다 · 중요

[analysis/stats.py:120] [analysis/stats.py:135] 기존 점유 규칙은 잠깐의 루즈볼에서 소유자가 흔들리지 않게 한다. 그러나 홈 A 확정 뒤 수초간 공이나 보정 좌표가 사라져도 매 프레임 A의 점유율이 늘어난다. 다시 보인 홈 B가 세 프레임 연속 후보가 되면 A→B 한 건이 생긴다. 공이 계속 보이는 긴 패스에서도 출발 프레임은 B 확정 바로 전 프레임이다. 이때의 A 좌표가 노드 평균에 들어가고, 연결선 클릭은 이미 공이 도착한 부근으로 간다.

**질문** 어느 시각까지 A의 마지막 접촉을 관측했다고 말할 수 있고, 어느 공백부터 양쪽 점유를 별개로 볼까? **선택지** 마지막 접촉과 수신 후보 시작을 따로 기록하고 허용 공백을 초 단위로 정하면 긴 패스를 일부 놓치는 대신 영상 근거가 분명해진다. 공 위치가 관측된 비행과 관측 자체가 끊긴 구간을 나눠 전자만 연결하면 긴 패스를 더 살릴 수 있지만 상태와 검증 사례가 늘어난다. 두 방식 모두 공백 뒤 새 구간과 이전 구간 사이 이벤트 생성까지 확인할 필요가 있다. **학습 개념** 패스 판정의 정밀도·재현율, 관측 시각과 확정 시각.

### ③ 수동 보정 중 이벤트 목록에서 다른 프레임으로 갈 수 있다 · 중요

**질문** 보정 중 장면을 바꾸면 작성 중인 점들은 어느 프레임에 속할까? **선택지** 목록도 기존 탐색 잠금 상태를 공유하면 편집 문맥을 보존하기 쉽다. 프레임 이동을 편집 종료 동작으로 제공하면 장면 탐색은 가능하지만 미저장 점의 처리 방식을 정해야 한다. **학습 개념** 화면 상태와 저장 대상의 불변조건.

### ④ 같은 영상을 다시 선택하면 분석 카드가 사라질 수 있다 · 중요

### ⑤ 골키퍼 하나로 확인한 방향도 팀 평균 위치가 덮어쓴다 · 권장

**경계 사례와 검증 한계.** 같은 선수의 연속 소유는 한 구간에 합쳐지고, 같은 팀의 다른 선수만 패스가 된다. 홈·원정 골키퍼는 점유와 히트맵에 들어가며 대형에서는 빠진다. 점유 판정은 팀만 검사하므로 심판 제외는 심판이 홈·원정으로 분류되지 않는다는 전제에 의존한다. 0명 또는 같은 팀 1명만 있으면 그 팀 안에 패스 쌍이 생기지 않고 필드 선수 2명 미만이면 대형도 없다. 화면의 빈 대형 안내는 이 경우까지 보정 단절로 표현한다.

지정된 Python 테스트는 빈 경기·턴오버·방향·위치 대체·등번호를 다룬다. 고정 위치 선수만으로는 출발 시각 오차를 가려내기 어렵다. 긴 공 결측, 단일 선수의 반복 소유, 골키퍼와 심판, 누적 경계 직후 수신을 독립적으로 검증하는 사례는 해당 파일에 없다. 프런트엔드 소스에서 이 순수 함수의 테스트 파일은 찾지 못했다. 허용된 pytest 명령은 이 환경에서 `python.exe`에 접근하지 못해 시작되지 않았다. 브라우저 결과는 저장 기록을 대조했다.

## 4. 다음에 공부해보면 좋을 주제

- **한 개의 합성 장면으로 여러 층 검증하기.** 움직이는 송신자, 짧은 루즈볼, 수신 확정, 긴 보정 공백을 한 타임라인에 놓고 예상 점유·패스·탐색 프레임을 먼저 손으로 표시해 보자. 같은 자료를 Python 집계와 JS의 이전 저장본 복원에 넣으면 어느 단계에서 차이가 생겼는지 찾기 쉽다.
- **분모와 좌표축을 먼저 설명하는 시각화.** 같은 선수가 하프타임 뒤 반대 진영의 같은 전술 위치에 서는 예를 그려 보자. 원본 피치 밀도, 공격 방향 기준 구역 비율, 볼 점유율이 각각 어떤 질문에 답하는지 구별할 수 있다.
