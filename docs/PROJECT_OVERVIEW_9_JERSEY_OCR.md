# 9부 — 등번호 인식 · 신원 부여

> **이전 문서**: [3부 21.4절 · 24절 로드맵 4번](./PROJECT_OVERVIEW_3_VLM.md) · [8부 — RF-DETR 파인튜닝](./PROJECT_OVERVIEW_8_RFDETR_FINETUNE.md)

트랙 ID 만 있던 선수에게 등번호를 붙이고, 같은 팀·같은 번호인 끊긴 트랙을 같은 선수로 잇는다. 정밀 모드에서만 동작한다.

## 모델

- **GLM-OCR** (`zai-org/GLM-OCR`, **MIT**, 0.9 B, bf16 약 2 GB). 메인 `.venv` 의 transformers 5.19 가 `GlmOcrForConditionalGeneration` 을 지원해 별도 환경이 필요 없었다.
- 가중치는 처음 쓸 때 자동으로 받는다 (PC: `C:\Users\PC\.cache\huggingface\hub\models--zai-org--GLM-OCR`, 커밋하지 않음).
- 프롬프트 `Text Recognition:`, 크롭을 3 배 키워 넣고 최대 6 토큰 생성. 신뢰도 = 생성 토큰 최대 확률의 곱.

## 방법 (`tracking/identity.py`)

```
분석 중 (5 프레임마다)  선수 박스 상단 12~60 % 크롭 — 박스 높이 ≥ 80 px, 다른 박스와 안 겹침, 화면에 안 잘림,
                        라플라시안 분산 ≥ 60 → 트랙당 품질(선명도 × 높이) 상위 12 장만 보관
트랙 잇기·팀 분류 뒤    GLM-OCR 판독 → 숫자 1~99 만 인정 ('1' 은 골키퍼 트랙만)
                        → 트랙별 신뢰도 가중 투표: 1 등 번호가 2 회 이상 · 전체 판독의 25 % 이상 ·
                          유효 판독 점수의 50 % 이상 · 평균 신뢰도 0.5 이상이면 확정, 아니면 미확정
                        → 같은 팀·번호가 같은 프레임에 둘이면 신뢰도 낮은 쪽 미확정
                        → 같은 팀·번호이고 시간상 안 겹치는 트랙은 가장 먼저 나온 ID 로 재연결
```

- 심판(탐지 라벨 referee)은 읽지 않는다. 팀이 `other` 인 트랙은 번호를 읽어도 재연결하지 않는다.
- **'1' 규칙**: 번호 없는 셔츠(심판·옆모습·무지 부분)를 OCR 이 '1' 로 읽는 일이 가장 흔했다. 1 번은 거의 항상 골키퍼라 골키퍼가 아닌 트랙의 '1' 판독은 버린다. 이 규칙 전에는 심판 2 명이 1 번으로 확정됐고, 가짜 '1' 이 진짜 번호(18)의 득표율을 깎아 미확정이 된 트랙도 있었다.
- 결과 JSON: `identities` {트랙 ID: {jersey_number(미확정 None), confidence, evidence(일치 판독 수), readings(읽은 크롭 수), merged(합친 트랙)}}, `identity` (모델, 크롭 수, 확정 수, 재연결 수, 시간).
- 화면: 영상 박스 칩 `#7 · 14`, 경기 지표 표 `#7 · 14번`. 질의: `player_stats(jersey_number=14, team=...)` 로 번호로 선수 지표를 찾고, 답변에 "#7(등번호 14)" 처럼 함께 말한다.
- 설정: `analysis.profiles.precise.jersey_ocr: auto` (GPU 면 켬), `gpu_models.ocr: zai-org/GLM-OCR`. 실시간 모드는 기본 꺼짐.

## 평가 — sports_video_1 (정밀 모드 전체 분석)

RF-DETR 파인튜닝 + SAM3 + SigLIP2 + GLM-OCR, RTX 5070 12 GB.

| 지표 | 값 |
|---|---|
| 크롭 수 / 판독한 트랙 | 464 장 / 46 트랙 |
| 트랙 수 (재연결 전 → 후) | 60 → **54** (6 개 재연결) |
| 번호 확정 트랙 | **15 / 54** (28 %), 심판 제외 15 / 47 (32 %) |
| 확정 트랙이 차지하는 선수 박스 (심판 제외) | **56.4 %** |
| OCR 단계 시간 | 34.6 s (크롭당 0.075 s) |
| 전체 분석 시간 | 446 s (+ 자동 보정 80 s) |
| 최대 VRAM | 3.9 GB (전체 파이프라인), OCR 만 2.1 GB |

확정 번호 — 바르셀로나(home): 3, 4, 6, 8, 14, 16, 18, 22 / 레알 마드리드(away): 3, 11, 14, 15, 19, 22. 두 팀 실제 명단 번호와 맞는 구성이다.

## 한계와 다음 단계

1. 번호가 크롭 한두 장에서만 보이는 트랙은 놓친다 — 확정 기준(2 회 이상)을 낮추면 오탐이 늘어난다.
2. 팀 분류가 `other` 로 남은 선수는 재연결하지 않는다 (SigLIP2 이상치로 빠진 선수 등).
3. GLM-OCR 판독을 라벨로 써서 경량 숫자 분류기(0~99)를 학습하면 더 빠르고 작은 번호에 강해질 수 있다 (3부 21.4절 4번).
4. 명단(이름)과 연결하는 기능은 아직 없다 — `(팀, 등번호)` 가 키가 된다.

## 사용

```bash
# 기존 분석 결과에 등번호만 붙이기 (탐지 없이, GPU 권장)
python scripts/identify_jerseys.py data/samples/sports_video_1.mp4 uploads/analysis/sports_video_1.mp4.json \
    --out uploads/analysis/sports_video_1.mp4.json --sheet-dir 확인용폴더 --sheet-tracks 26
```
